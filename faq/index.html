Data science words

What do EDA, supervised, classification, unsupervised and clustering mean in this lab?

  • EDA (exploratory data analysis): we look before we model. Our first Gemma table and Mission 1's bar chart are EDA.
  • Supervised learning: we learn from examples that come with the answer, called the label. In Mission 2, the label is "did a lesson happen within 2 hours?"
  • Classification: supervised learning where the answer is a category. Ours is yes/no, so XGBoost, logistic regression and random forest are all classifiers here.
  • Features: what we know before the reminder goes out, like which reminders were eligible and how many were sent last week.
  • Train / test split: we learn on earlier days and grade on later days, like studying old exams and then taking a new one.
  • Data leakage: letting the model peek at the answer by accident. It looks amazing on paper and fails in real life.
  • Unsupervised learning: finding structure with no labels at all.
  • Clustering: one kind of unsupervised learning that groups similar things. In the bonus, k-means groups reviews that use similar words.

What is TF-IDF?

It's the classic way to turn text into numbers a model can use. TF (term frequency) counts how often a word appears in one review. IDF (inverse document frequency) is high for words that are rare across all reviews and low for words that are everywhere. Multiply them, and common words like "app" fade out (it's in more than half the reviews, so we drop it), while words like "hearts" or "ads" stand out. Then a supervised model, like logistic regression, learns which word scores go with 1–2 star reviews. That's why it needs labels: 7,999 of them in our run.

How does XGBoost work, and why did it beat logistic regression and random forest?

XGBoost is gradient boosting with decision trees. The first small tree makes a rough guess, the next tree focuses on the rows the first one got wrong, and so on. Our 180 small trees add up to one prediction.

  • Logistic regression adds up the features with one weight each. It can't easily see combinations like "eligible for A and reminded yesterday" unless we build that feature by hand.
  • A random forest grows many deep trees independently and averages them. It handles combinations, but each tree is trying to solve the same problem from scratch, so they all chase the same easy patterns.
  • XGBoost keeps aiming new trees at the leftover mistakes, so it squeezes out a bit more.

On the same features and the same 2,000 later sends: logistic regression AUC 0.775, random forest 0.774, XGBoost 0.785. The edge is small (about 0.01), but the 95% interval stays above zero for both comparisons. Most of XGBoost's gain came from which reminders were eligible (about 55%) and how many recent reminders a learner had (about 33%).

What did the clustering bonus find?

With only TF-IDF word scores and no stars, k-means made 5 groups. Afterwards we peeked at the stars: a "learning, fun, languages" group averaged 4.5★, while a "hearts, practice, earn, watch, ads" group averaged 1.9★, and 77% of it was 1–2 stars. Clustering found the angry-about-hearts group without ever seeing a rating. But we picked 5 groups ourselves, and a different number gives different groups, so we read the reviews before naming anything.

Big ideas

Why isn't the tallest bar, template C, the winner?

C has the highest raw rate (about 40%), but in the earlier logs C was sent only when it was the single option a learner could get (575 sends, 1.4% of all sends). Nobody chose C over anything else, so its bar describes a special group of learners. It doesn't show that C works better.

Why do we compare A and G only where both were possible?

Duolingo picked at random among the reminders each learner was eligible for. Different templates reach different people, so raw rates mix up "which message" with "which learner". If we keep only sends where both A and G were on the table, the coin flip between them is fair. In that fair view, A gets 19.7% and G gets 22.7%. The gap is −3.0 points, but the 95% interval runs from −6.1 to +0.1, so there's no clear winner yet.

Gemma's code ran fine. What was wrong with it?

It used .str.contains("A") on a column that holds lists, so it matched nothing and quietly returned an empty table. No error, no warning. Code that runs isn't automatically code that's right. We read the filter and check the counts every time.

Why does Jev lose on the send logs but win on the reviews?

Our rule of thumb: could a person answer from one row?

  • A send log row is just IDs and numbers ("eligible A, G · sent G · 0.12 days"). There's nothing to read, and the signal only shows up as a pattern across thousands of rows. A trained model wins: XGBoost AUC 0.79 vs Jev 0.51.
  • The biggest pattern is a quirk of this dataset: learners eligible for A finished a lesson about 21% of the time, versus about 4% for everyone else. Only a model that sees labels can find that.
  • Jev's guesses also sat between about 31% and 42% for most rows (the real rate was 16.5%). When everyone gets nearly the same score, nobody gets ranked, so AUC lands at a coin flip.
  • A review is words a person can read ("love it, but the ads…"). Jev, with zero labels, beats a text model trained on 7,999 labels: AUC 0.948 vs 0.927. It also guesses star ratings closer (average error 0.50 vs 0.75 stars).

What is IPS, in one sentence?

We score a new plan only on the sends where it happens to agree with what was actually sent, and we give each match a weight equal to the number of options there were (3 options means a weight of 3).

Why does our plan's promise shrink?

The plan always picks the template with the best past rate. On the earlier data its own rate table promises +3.1 points over random. An honest IPS check on that same data gives +0.6, and on later data it lands at −1.2. When we pick the highest of many noisy estimates, we tend to pick the luckiest one. That's why we freeze a plan and test it on new data.

What's a bandit, and why should we care?

A bandit keeps trying a mix of options so it keeps learning which one works. Duolingo's version is "sleeping" (some reminders aren't available for some sends) and "recovering" (a reminder feels fresh again after a break). Because it picks at random among eligible reminders, we can evaluate new plans offline with IPS.

The data

Are the A–L messages real?

The IDs are real; the wording on our slides is not. Duolingo never released the text behind A–L. We wrote made-up wording (marked 🎭) so the IDs are easier to picture. You can turn it off on the Mission 1 slide. The numbers are real, so please don't read the results as "urgent beats gentle".

Then what are the message cards on "What learners actually see"?

Those are real Duolingo messages published in the paper or on Duolingo's blog, each linked to its source. We just can't tell which A–L ID, if any, they belong to.

Are the reviewers the same people who got the reminders?

No. The reminder logs are from 2020 and the reviews are from 2025. They're separate public datasets. We use them to walk through one workflow, so we connect the steps, not the learners.

Why is the later success rate (16.5%) so much higher than the earlier one (9.6%)?

Time and sampling. The two periods come from different archives and different days. It isn't the effect of any campaign.

Is this how Duolingo actually decides what to send?

Not exactly. Duolingo's real system is the bandit described in the KDD 2020 paper. Our plan, LP and feedback room are simplified teaching versions built on their public data.

Gemma and Jev

What's the difference between Gemma and Jev?

Gemma is a chat LLM: it writes text, like code and explanations, so we read what it writes. Jev is a judgment model from TypeSafe AI: we give it something to read and a question, and it gives back a typed answer. That answer is a probability (Noul), a position on a scale (Score), or a category (Choice). Jev doesn't chat or write code.

Couldn't we just ask Gemma for a probability?

We could, and it might type "0.7". But that's text we'd have to parse and then check for calibration ourselves. Jev returns the probability as a field, so we can score it next to XGBoost right away.

How much did Jev cost?

TypeSafe lists $42 per billion input tokens. Our 2,000 log rows cost about $0.06, and 500 reviews × 3 questions cost about $0.02.

Are Jev's review topics accurate?

We don't know yet. Nobody has checked the Choice topic tags against human labels, so we treat them as drafts that tell us which reviews to read first.

Can I tune my model until it beats the test set?

Please don't. We fix our choices before we look at test results. If you want to tune, split off a validation set from the earlier data.

Troubleshooting

My own prompt shows the recorded example instead of a new answer

That means no Gemini key is connected. Add GEMINI_API_KEY (see the README, Step 2) and run the cell again. The recorded example is always labeled so you know which one you're seeing.

Gemma sometimes fails with a server error

The free API has short hiccups. The helper retries automatically; if it still fails, wait a few seconds and run the cell again.

Colab asks me to upload the zip again

Colab forgets files when the runtime restarts. Upload the original lab03_starter.zip again when the first cell asks.

The companion looks plain when I open it offline

Open companion/index.html from the unzipped folder. Everything works offline; only the rounded font needs internet, so the page falls back to a system font.
