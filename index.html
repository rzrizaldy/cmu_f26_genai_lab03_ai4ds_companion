Interpret these scores
AUC measures ranking; 0.5 is chance. Compare average precision with the positive rate. Brier measures probability error. A constant training-rate predictor is a useful baseline.
JEV sees base pre-send features; engineered models also learn rates from training labels. No prompt or hyperparameter was selected using test labels. The interval uses a paired row bootstrap, so learner-level dependence is unaccounted for. Runtime comes from one CPU/API run.

A model predicts completion well. What follows?


The proposal meets later data.
Freeze a simple policy: for each send, select the highest estimated language/template rate among eligible options. This maximizes a one-round objective with exactly one eligible template per send. The estimates may still favor the wrong option.
Only one outcome is observed
Eligible A, G, L→Log sent G
A proposal that selects A has no observed A outcome for this send. Offline evaluation uses rows where the proposal matches the log, weighted by the inverse logging probability.
If 3 templates were eligible, a matching row gets weight 3.
The score estimates one-step value under historical logged contexts. Repeated deployment changes notification history.
Frozen policy, future-period check
Why two offline estimates?
IPS divides weighted successes by all sends. SNIPS divides by the sum of weights. Both use known uniform logging probabilities. Effective sample size shows how concentrated the weights are; it is not a count of unique learners.
The promise shrinks every time we check honestly
Same frozen policy. Gap = policy minus random sends, in percentage points.
Picking the highest estimate tends to pick the luckiest estimate. The rate table looked great on the data it was built from.


Why were the logs random? Duolingo runs a bandit.
A bandit keeps sending a mix of templates so it keeps learning which one works. The paper names two twists.
SleepingSome templates are unavailable for some sends.
RecoveringA template regains novelty as days pass since a learner last saw it.
Random logsThe released sends were picked randomly within each eligible set. That is what makes IPS possible.
Keep watching the outcome
These are real later-period aggregates. A change suggests a question to investigate. The dataset has no outage labels or delivery diagnostics.
